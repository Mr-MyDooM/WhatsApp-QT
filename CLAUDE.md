# CLAUDE.md

Pairline (repo and crate still named WhatsApp-QT) is a macOS-first desktop client that wraps WhatsApp Web (`https://web.whatsapp.com`) in a Tauri 2 window: Rust backend, React frontend for the app chrome, one system webview per account, tray icon, persistent settings. Bundle ID `dev.mj.pairline`.

## Build and Run

1. Get a Rust toolchain, Node, pnpm, and the Tauri CLI: `cargo install tauri-cli --version "^2" --locked`. Done when `cargo tauri --version` prints 2.x.
2. `cargo tauri dev`. Done when the main window opens. `beforeDevCommand` installs and starts the Vite dev server in `frontend/`.
3. Build the bundle: `cargo tauri build` (or `packaging/macos/build-macos-app.sh`). Output is in `target/release/bundle/{macos,dmg}`.
4. For backend logs, run with `RUST_LOG=debug`. Without `RUST_LOG`, `env_logger` prints errors only, so a silent run is not proof nothing went wrong.

Notifications, the sound test, and mic and camera prompts work only from the bundled `.app`. The dev build reports `no_bundle`.

There is no CI. Verify builds locally, on macOS first. Checks before each commit, each must exit 0:

- `cargo fmt --check` (default `rustfmt` settings, no `rustfmt.toml`)
- `cargo test`
- `cargo clippy --all-targets -- -D warnings`
- `pnpm --dir frontend build` (runs `tsc --noEmit`, then Vite)

## Architecture

### Rust Backend (`src/`)

- **`core.rs`**: pure app core with no Tauri types. One entry point, `Core::handle`: event in, effects out. Holds settings (de)serialization, theme CSS, and limits for untrusted page input. Most tests live here.
- **`main.rs`**: the Tauri shell. Builds the window, the sidebar, title bar and account webviews, the tray, and the menus. `dispatch` sends an `Event` to the core and `run_effects` carries out the returned `Effect`s. Holds every `#[tauri::command]`.
- **`notify.rs`**: native notifications. macOS uses `UNUserNotificationCenter` (objc2); other platforms use `notify-rust`.
- **`avatar.rs`**: account profile pictures sent by the remote page. Checks the data URL, limits the call rate, stores one file per account in the app data folder.
- **`dock.rs`** (macOS only): the Dock menu, added to tao's app delegate at runtime.
- **`*_shim.js`**: scripts injected into each account webview (`include_str!` in `main.rs`): notification bridge, own avatar, chat list resize, spellcheck off. A setting that changes live (chat list width, spellcheck) is sent to every account page with `eval`.

### Frontend (`frontend/`)

React 19, TypeScript, Tailwind and shadcn-style components, built with Vite into `frontend/dist`. Pages: `index.html` (sidebar), `settings.html`, `rename.html`, `error.html`. See `docs/adr/0002`.

### Accounts and data

- Each account has a stable UUID. Its webview label is `account-<uuid>`.
- macOS: each account uses `data_store_identifier(uuid bytes)`, stored at `~/Library/WebKit/<process name>/WebsiteDataStore/<uuid>`. The dev build process is `WhatsApp-QT`, the bundle is `dev.mj.pairline`, so dev and bundle logins are separate.
- Other platforms: `data_directory` at `<app data>/accounts/<uuid>`.
- Settings: `<config dir>/WhatsAppDesktop/settings.json`. Data deletes that fail go to `pending_deletions` and run again at the next start.
- Downloads go to `download_path` (set in `on_download`). Empty or a missing folder means the system Downloads folder.
- Never force a QR re-scan: a change that moves or resets the data store logs every account out.

### Commands and permissions

The app uses an app manifest, so each new command needs all three:

1. An entry in the `AppManifest` commands list in `build.rs`.
2. An `allow-<kebab-name>` permission in the right file in `capabilities/`. `remote.json` is the only one that grants anything to the remote WhatsApp page (`account-*`); keep it minimal, because that page is untrusted.
3. An entry in `invoke_handler` in `main.rs`.

`tauri-build` writes `permissions/autogenerated/<command>.toml`. These files are tracked: commit them.

Tauri is pinned exactly (`=2.12.4`) because the `unstable` child-webview API can change in a minor release.

## Platform Notes

- macOS 14+: first-class support. Check every change here first. Bundles are ad-hoc signed (`signingIdentity "-"`) and not notarized. `Info.plist` at the root is merged into the bundle (mic and camera usage strings); `Entitlements.plist` holds the entitlements.
- Linux and Windows: paused. The code is kept but not tested.
- `packaging/` deb, rpm, AppImage and Flatpak scripts still package the old Qt app and do not work with the Tauri build. Rework them when Linux work starts.

### Deep links (`whatsapp://`)

`tauri-plugin-deep-link` registers the scheme (`plugins.deep-link` in `tauri.conf.json`). `tauri-plugin-single-instance` with the `deep-link` feature sends a second launch's URL to the running app.
